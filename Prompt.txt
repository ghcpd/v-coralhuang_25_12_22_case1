## API Change

This is a **confirmed API bug** that results in **schema instability**.

The endpoint:

* `GET /api/users/<id>`

returns **different response structures for the same endpoint and method**, depending on request context.

Returning inconsistent payloads for successful (2xx) responses, without versioning or signaling, violates the API contract and has caused production regressions.

---

## Observed Variants

The same endpoint may return:

1. **200 OK** user object with `email` present
2. **200 OK** user object with `email` missing
3. **200 OK** user object with `email="***REDACTED***"`
4. **401** JSON error response (missing/invalid token)
5. **429** JSON error response with retry information

There is no explicit indicator distinguishing these variants.

---

## Legacy Client Assumptions (Fixed)

Legacy clients assume:

* Successful responses have a stable schema
* `email` always exists and is a valid email
* `about_me` is always a string
* Any non-200 response indicates an outage

These assumptions are no longer valid due to the API bug.

---

## Constraints

* Backend API behavior cannot be changed
* Legacy client code cannot be changed
* A compatibility layer must be introduced to mitigate the bug

This layer exists solely to restore a stable contract for legacy consumers.

---

## Compatibility Expectations

### Successful Responses (2xx)

* Missing or redacted `email` should be handled so legacy clients remain functional
* `about_me` must be a string
* Legacy consumers must see a consistent set of core fields:

  * `id`, `username`, `email`, `about_me`, `last_seen`

How this normalization is implemented is up to you, as long as the contract is restored.

---

### Error Responses

Error responses must be normalized into a legacy-friendly structure:

```json
{ "error": "<short>", "message": "<detail>" }
```

They should also be classified in a way that avoids false production outages (for example, distinguishing client errors and transient conditions from real outages).

## Idempotency

You are expected to demonstrate this property through tests.
