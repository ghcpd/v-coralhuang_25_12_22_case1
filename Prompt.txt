## API Change

This is an **API schema instability regression** caused by **context-dependent response fields**.

The API endpoint:

* `GET /api/users/<id>`

returns **different response schemas for the same endpoint and method**, depending on request context.

### Observed Behavior

* When a user requests **their own profile**, the response includes the field:

  * `email`
* When a user requests **another user's profile**, the response **omits** the `email` field entirely
* The API returns **HTTP 200** in both cases
* There is **no versioning, no feature flag, and no explicit indicator** of schema variance

This behavior is implemented server-side and is not documented as a versioned API change.

---

## Legacy Client Assumptions

Legacy clients assume:

* `/api/users/<id>` always returns a **stable schema**
* Field `email` is **always present**
* Missing fields indicate malformed or incomplete data
* HTTP 200 implies full schema compatibility

These assumptions are now invalid and have already caused production failures.
