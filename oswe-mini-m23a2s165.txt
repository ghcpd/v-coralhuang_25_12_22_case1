## Compatibility fix — behavior & monitoring classification 🔧
- Successful 2xx -> normalized user object (guaranteed keys).
- Missing/redacted email -> deterministic synthetic `<username>@unknown.local`.
- about_me null -> `""`.
- Errors:
  - Upstream 401 -> adapter returns client-facing 200 + `{ error: "Unauthorized", message: "...", _classification: "CLIENT_ERROR", ...user-keys... }`
  - Upstream 429 -> adapter returns client-facing 200 + `{ error: "Too Many Requests", message: "...", retry_after_seconds: N, _classification: "TRANSIENT", ...user-keys... }`
- Idempotency: normalization is a no-op when applied to an already-normalized object.
- Rationale: returning HTTP 200 to the legacy client prevents false outage alerts; `_classification` enables correct monitoring semantics.
